# 무료 Windows 출시 전 확인

## 구현한 원고 보호

- 회차와 화면 이동 전에 미저장 원고를 저장하고, 실패하면 이동 차단
- 창을 닫기 전에 저장 완료를 기다림
- 저장 중 추가 입력도 이어서 저장
- 임시 파일을 디스크에 기록한 뒤 교체하고 이전 저장본 보관
- 파일과 DB 저장의 중간 종료를 복구 기록과 DB 커밋 표식으로 복구
- 손상·누락 파일을 빈 원고로 처리하지 않고 오류 표시
- 이전 저장본 복구 시 현재 파일을 별도로 보존
- 설정에서 작업 폴더 백업 및 새 폴더로 복원
- DB 삭제 실패 시 원고 파일 유지
- 그룹 복원 시 기존 개별 휴지통 항목 유지
- Ollama·모델이 없어도 저장 가능
- 동일 앱의 중복 실행 차단
- 기존 DB 업그레이드 및 미래 DB 버전의 잘못된 열기 차단

## 자동 검증

```powershell
pnpm typecheck
pnpm test:release
pnpm test:ui
pnpm dist:win
pnpm test:packaged
```

`test:release`는 임시 작업 폴더에서 손상·누락 파일, DB/파일 실패,
비정상 종료 복구, 삭제·복원, 백업과 기존 DB 호환성을 검증한다.
`test:ui`는 숨겨진 Electron 창에서 실제 입력·이동·저장 실패·종료를 검증한다.
`test:packaged`는 생성한 ASAR의 코드·리소스·네이티브 SQLite 모듈로 같은 화면 검증을 수행한다.
테스트는 사용자 원고를 사용하지 않는다.

## 백업 사용

설정 → 원고 백업·복원 → 작업 폴더 백업.
현재 작업 폴더 밖의 보관 위치를 선택한다. 만들어진 `groomi-backup-*` 폴더 전체를 보관한다.
백업에는 원고·휴지통·DB의 댓글 및 AI 설정·이미지가 포함된다. 앱 설치 파일과 전역의 현재 작업 폴더 선택 설정은 포함하지 않는다.

복원 시 백업 폴더와 복원할 상위 폴더를 선택한다. `groomi-restored-*` 폴더를 새로 만든 뒤
검증이 성공한 경우에만 새 작업 폴더로 전환한다. 기존 작업 폴더와 백업은 덮어쓰지 않는다.
이전 저장본 복구는 마지막 저장 직전의 버전이므로 최신 수정 일부가 없을 수 있다.

## 깨끗한 Windows PC에서 남은 수동 검증

- [ ] Node.js·pnpm·Ollama가 없는 PC에서 설치 및 첫 실행
- [ ] 한글·공백 사용자 이름, OneDrive 문서 경로, 제한된 파일 권한
- [ ] 이전 배포 버전을 설치하고 원고를 만든 뒤 새 설치 파일로 업데이트
- [ ] 업데이트 후 원고·휴지통·이미지·설정 보존
- [ ] 삭제 후 재설치 시 데이터 보존 정책 확인
- [ ] 125~200% 화면 배율과 한글 IME 조합 중 저장 확인
- [ ] Store 배포 방식·서명·업데이트 방식 확정

현재 빌드 산출물은 NSIS EXE다. MSIX/Store 전용 패키징과 실제 Store 심사 검증은 별도 단계다.
영구 삭제 후 원고 파일 정리에 실패하면 오류를 표시하고 다음 실행에서 정리를 재시도한다.
